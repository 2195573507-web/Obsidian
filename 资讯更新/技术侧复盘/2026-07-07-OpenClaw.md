## 最重要 5 条

1. **OpenSSH 10.4 与 Ubuntu OpenSSH 安全修复都值得纳入维护窗口**
   - OpenSSH 10.4 官方发布说明包含 sftp/scp/internal-sftp/GSSAPIAuthentication/key reexchange 等安全修复，并带来 seccomp sandbox、post-auth re-key、`sshd -G` 输出等兼容性变化。
   - Ubuntu 同日安全公告 USN-8514-1 修复 OpenSSH legacy scp/root 下载场景下的权限处理问题。
   - 行动：不要在核心服务器直接裸升；先确认发行版包状态，备份/导出 `sshd` 配置，测试登录、sftp/scp、自动化脚本和 seccomp 兼容。

2. **AI Agent 数据外传风险正在从“模型内容”转向“渲染层/工具层”**
   - NVD CVE-2026-14898 显示 OpenAI Codex macOS 桌面端曾因渲染模型响应中的远程 Markdown 图片，可能把 API key、源码或工具返回数据编码到远程图片 URL 中外传；PromptArmor 披露称问题已修复。
   - 行动：OpenClaw/Hermes 的 Markdown 图片、HTML 预览、browser/canvas 渲染、消息转发、Obsidian 预览等路径，应默认阻断或隔离模型输出里的远程资源自动加载。

3. **基础设施“胶水层”今天风险集中：Python、tar、gzip、socat、7-Zip**
   - Ubuntu 发布 Python、tar、gzip、socat 多项安全修复；GitHub Security Lab 披露 7-Zip 26.00 多个漏洞，26.01 已修复。
   - 风险共同点：自动解包、备份恢复、CI artifact 分析、临时端口转发、脚本化运维常以高权限运行，单个基础工具漏洞可能扩大影响。
   - 行动：优先更新基础包；把不可信归档解包放进隔离目录和低权限用户；检查是否有长期暴露或遗留的 socat 监听。

4. **开源 Agent 工程化生态继续升温：skills、跨 Agent 委派、终端多 Agent runtime**
   - GitHub Trending 中 `addyosmani/agent-skills`、`openai/codex-plugin-cc`、`ogulcancelik/herdr` 等项目显示，AI 编码工具正在从单次对话转向可安装技能、互审/委派、可恢复终端运行时。
   - 行动：OpenClaw/Hermes 可以继续强化 skill、cron、subagent、verification gate、可恢复会话和状态聚合；但 herdr 等 AGPL 项目要注意许可边界，先学习设计，不直接复制代码。

5. **本地/私有推理与轻量子模型值得跟踪，但生产升级要保守**
   - Ollama `v0.31.2-rc1` 涉及 CUDA/JetPack、ROCm、MLX、llama.cpp、agent harness 等变更；JetBrains Mellum2 作为 12B/2.5B active MoE 开放模型，适合 routing、RAG、summary、sub-agent 任务候选；NVIDIA Nemotron-Labs Diffusion 展示扩散/自推测推理方向。
   - 行动：把 Mellum2/Nemotron 作为实验候选；Ollama RC 只在非核心节点验证 GPU/驱动/ROCm/CUDA 兼容，不建议直接升级主服务。

## 对 OpenClaw / Hermes / 个人服务器有用的 3 条

1. **给 OpenClaw/Hermes 增加“远程资源外连”安全测试用例**
   - 构造 Markdown image exfiltration、隐藏 HTML、schema prompt、搜索结果污染 fixture。
   - 验证消息渲染、浏览器工具、Canvas、Obsidian 写入、QQ 转发不会因模型输出自动外连或泄露上下文。
   - 对不可信内容默认转义、代理隔离或显式确认。

2. **把服务器维护优先级放在 SSH、归档、Python、socat、KVM 上**
   - 安全更新优先级：OpenSSH、Python、tar、gzip、socat、7-Zip/归档处理工具。
   - 若个人服务器运行 KVM/nested virtualization 或不可信 VM，跟踪 Januscape / CVE-2026-53359 对当前宿主机内核的影响。
   - 所有升级前先确认发行版修复包和回滚路径；本复盘不建议直接修改生产配置。

3. **把 monitor/Hermes 网关做成“治理与观测平面”，不是单纯状态页**
   - 今日学习报告强调：API 可用性、错误率、首 token 延迟、断流率、上游 429/5xx、活跃流式连接、请求堆积，比单纯 CPU/内存更接近用户痛点。
   - Nginx/SSE/OpenAI streaming 路径要单独观测 buffering、read timeout、heartbeat、chunk gap、慢客户端和 FD/worker connection 压力。
   - 网关能力可参考 LiteLLM/Portkey：virtual key、model alias、routing/fallback、usage/spend ledger、request_id/trace、错误分类。

## 风险 / 机会

### 风险

- **渲染层外传成为 Agent 系统的高优先级风险**：远程图片、HTML、schema markup、网页搜索污染都可能把上下文、密钥片段或工具输出变成网络请求参数。
- **供应链攻击更像正常开发活动**：PolinRider 报告显示攻击会利用合法仓库/维护者账号、历史重写、VS Code tasks、混淆 JS、伪 `.woff2` 等方式，不能只看 star、README 或仓库外观。
- **自动解包与基础工具漏洞容易被低估**：tar/gzip/Python/7-Zip 漏洞会影响备份恢复、CI、附件处理、日志归档等高频路径。
- **RC/新范式模型不适合直接进生产**：Ollama RC、扩散语言模型、自推测推理、轻量 MoE 都需要本地基准和回滚预案。

### 机会

- **把 Codex CVE 模式转成 OpenClaw/Hermes 安全回归集**：这是可执行、低成本、对 Agent 系统很有针对性的加固点。
- **建立轻量供应链巡检脚本**：扫描 lockfile diff、postinstall、VS Code tasks、混淆 JS、异常字体/二进制、大行、历史重写迹象，优先覆盖插件和技能仓库。
- **把多 Agent runtime 经验产品化**：skill、subagent、cron、会话恢复、状态聚合、verification gate 可以形成 OpenClaw/Hermes 的差异化能力。
- **利用本地轻量模型降低日常任务成本**：Mellum2 等模型可作为 routing、摘要、RAG 压缩、日志分类、工具选择预判候选，先离线评估中文与工具调用表现。
