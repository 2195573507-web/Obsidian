1. OpenAI 发布 `gpt-realtime-2.1` 与 `gpt-realtime-2.1-mini`

   - 影响：如果 SGLang 支持稳定，可能成为高吞吐低延迟本地/私有推理的新方向；当前更适合实验评估，不宜直接替换生产模型。

## 对 OpenClaw / Hermes / 个人服务器有用的 3 条

1. 本地 Ollama 升级要谨慎验证 GPU 栈
   - `v0.31.2-rc1` 涉及 CUDA、JetPack、ROCm、MLX、llama.cpp 更新。对个人服务器最实用的动作是先记录当前 `ollama --version`、GPU/驱动/ROCm/CUDA 状态，再在非核心节点测试 RC。
   - 对 Hermes：`agent: harness core` 和历史 `ollama launch hermes-desktop` 方向值得继续跟踪，但不建议在主服务直接上 RC。

2. Mellum2 可作为“便宜子模型”候选
   - OpenClaw/Hermes 常见任务如 intent routing、短摘要、RAG 压缩、工具选择预判、日志分类，不一定需要前沿模型。Mellum2 的 12B/2.5B active MoE 结构和 Apache 2.0 许可适合进入候选池。
   - 建议：等 GGUF/Ollama/llama.cpp 或 vLLM 支持情况清晰后，用本地中文任务集和工具调用任务集做基准。

3. Realtime API 更新适合语音入口，但成本和供应商依赖要单独隔离
   - `gpt-realtime-2.1-mini` 可能降低语音 Agent 的延迟和费用。若 Hermes 后续做语音控制、会议摘要、实时对话，可以作为云端候选。
   - 建议：把实时语音作为可替换 provider，避免直接绑定单一 API；对隐私内容默认走本地/离线路径。

## 风险 / 机会

### 机会

- 轻量子模型架构更成熟：Mellum2 这类专门用于 routing/RAG/sub-agent 的模型，能让 Agent 系统从“一个大模型干所有事”转向多模型流水线，降低成本和延迟。
- 本地推理优化继续加速：Ollama/MLX/llama.cpp 更新、Nemotron diffusion/self-speculation 等方向，说明私有部署的吞吐和交互体验仍有改进空间。
- 实时语音模型进入 reasoning 化：OpenAI Realtime 更新改善噪声、打断和识别，对真实语音 Agent 可用性关键。

### 风险

- Ollama RC 变更包含 GPU 后端与 ROCm 支持调整，个人服务器直接升级可能引入兼容问题；生产环境应等待稳定版或先做回滚预案。
- 扩散语言模型仍是新推理范式，SGLang 支持仍在推进；短期内可能存在部署链路、采样行为、评估口径不稳定。
- Agent/MCP 生态继续快速变化，SDK beta 与工具协议差异会影响兼容性；工具权限、错误语义、审批默认值必须显式管理。
