## 对 OpenClaw / Hermes / 个人服务器有用的 3 条

### 1. 优先做 vLLM + Transformers 兼容性验证

vLLM 0.25.0 与 Transformers 5.13.1 在同一窗口发布，且 Transformers 补丁明确服务于最新版 vLLM。建议在非生产环境验证：

- 当前已用模型是否能正常加载。
- OpenAI-compatible streaming 是否行为一致。
- 自定义模型、legacy layer type、自定义 code 路径是否修复或出现新兼容问题。

### 2. llama.cpp 新构建适合检查本地/边缘推理矩阵

llama.cpp b9968 覆盖 OpenVINO、ROCm、CUDA、macOS、Android 等资产。个人服务器如果有 Intel GPU/CPU、AMD GPU 或 ARM 边缘设备，可把该版本列入候选测试，但应先保留旧二进制回滚路径。

### 3. LiteLLM rc 暴露了模型网关方向：MCP、路由、观测、签名验证

LiteLLM v1.93.0-rc.1 的重点不只是模型列表，而是网关能力：MCP auth bridge、复杂度路由、OpenTelemetry GenAI 异常事件、Redis 协调、rate-limit headers、cosign 镜像签名。Hermes/OpenClaw 如果未来统一外部 API、本地模型、MCP 工具代理，这些方向值得跟踪，但 rc 版本只建议实验。

## 风险 / 机会

### 机会

- 本地与自托管推理继续成熟：vLLM、llama.cpp、SGLang、LiteLLM 都在围绕高吞吐、多硬件、多模型网关快速迭代。

### 风险

- 多个关键更新是预发布或高频滚动构建，生产环境直接升级风险较高。
- 本地推理栈版本耦合增强：vLLM、Transformers、CUDA、PyTorch、模型自定义代码之间可能出现隐性兼容问题。
- MCP / Agent / Gateway 相关改动涉及认证、凭据转发、工具调用权限；需要额外关注 SSRF、凭据泄露、越权调用与日志脱敏。
