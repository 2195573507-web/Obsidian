## 对 OpenClaw / Hermes / 个人服务器有用的 3 条

1. **优先排查公网 Web 管理面与 CMS 插件**  
   - CISA 过去 24 小时新增的 KEV 都是文件上传导致 RCE 类型，且集中在 Joomla 生态组件。个人服务器应检查是否运行 Joomla、Balbooa Forms、iCagenda 或类似上传插件。
   - 建议：列出公网 vhost、容器、反代 upstream；确认上传目录不可执行；Nginx 对 upload/media 目录禁用 PHP/脚本执行。

2. **容器宿主机要尽快核对 runc / containerd / Docker Engine 版本**  
   - 即便暂无野外利用报告，容器逃逸类漏洞对 OpenClaw/Hermes 这类长期在线服务影响面较大。
   - 建议：检查 `runc --version`、`containerd --version`、`docker version`；优先升级到发行版安全仓库版本；能用 rootless 或 user namespace 的服务优先启用。

3. **监控侧补一类“异常符号链接 / procfs 写入 / 容器启动参数”检测**  
   - runc 漏洞利用链涉及 symlink race、`/dev/null`、`/dev/console`、`/proc` 等敏感路径。
   - 建议：在审计规则、Falco/Sysdig、EDR 或自定义日志中关注容器启动期间对 `/proc/sysrq-trigger`、`/proc` 写入、异常 mount/symlink 行为。

## 风险 / 机会

- **高风险：公网插件 RCE**。CISA KEV 新增项有明确“已知被利用”属性，且补丁窗口短；若服务器跑 CMS 或老旧 PHP 插件，应先查。
- **中高风险：容器逃逸补丁滞后**。runc 类漏洞通常依赖一定容器创建能力，但一旦攻击者能推送镜像、控制 Dockerfile 或创建容器，影响会扩大到宿主机。
- **中风险：K8s ingress / CSI 历史漏洞积压**。过去 24 小时未见 K8s 官方新增 CVE，但 2026 年 ingress-nginx 与 CSI 相关漏洞较多，适合做一次组件版本基线。
- **机会：把每日资讯转成自动检查项**。可把 CISA KEV、Docker Security Announcements、Kubernetes CVE Feed 固化为每日任务来源，并追加本机版本核对结果，减少“知道漏洞但没落地检查”的断层。
