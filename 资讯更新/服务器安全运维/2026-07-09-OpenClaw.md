## 最重要 5 条

### 1. runc 披露 3 个高危容器逃逸 / 主机 DoS 漏洞

- 涉及：CVE-2025-31133、CVE-2025-52565、CVE-2025-52881。
- 影响面：runc 是 Docker、containerd、Kubernetes、CRI-O 等容器栈底层运行时，影响自建 Linux 容器主机和多数云上节点镜像。
- 风险：攻击者需要能启动特制容器或控制镜像/构建流程；成功后可能写入宿主机 `/proc/sysrq-trigger` 导致主机崩溃，或通过 `/proc/sys/kernel/core_pattern` 等路径实现容器逃逸。
- 修复：上游 runc 已发布 1.2.8、1.3.3、1.4.0-rc.3 修复；runc 1.1.x 及更早版本不再支持。
- 状态：BleepingComputer 引述称目前未见在野利用报告；应按高优先级处理。

### 2. CISA KEV 7 月 7 日新增多项已被利用漏洞，暴露面偏 Web/远程管理

- CISA KEV 首页显示 2026-07-07 新增：Adobe ColdFusion 路径穿越、Joomlack Page Builder 访问控制问题、Langflow 授权绕过、JoomShaper SP Page Builder 任意文件上传等。
- 风险：这些不是 Linux/Docker 本身漏洞，但对个人服务器常见的 Web 面板、低代码/AI 工具、CMS 插件有直接意义；KEV 表示已有被利用证据。
- 建议：优先盘点是否暴露 ColdFusion、Joomla 插件、Langflow 或类似外网可访问后台；没有使用也应确认没有遗留容器、测试服务或反向代理入口。

### 3. AKS 7 月 7 日公告：Ubuntu 22.04 节点 Linux kernel CVE 扫描结果大幅增加

- Microsoft AKS 安全公告 AKS-2026-0005 称，Ubuntu/Canonical 近期重新分类大量内核 CVE，导致 AKS Ubuntu 22.04 节点镜像出现大量新增扫描发现。
- 关键点：这更多是分类/评估变化，不一定代表 AKS 特定补丁滞后；很多 CVE 仍无上游修复，升级 Kubernetes 或节点镜像不一定立刻清零。
- 运维意义：遇到扫描器“突然爆红”时，需要按实际内核包 `linux-azure` 版本核对 Ubuntu CVE Tracker，而不是只看泛化的 `linux` 包名。

### 4. GKE 近期安全公告延续提醒：containerd / Linux kernel 容器边界风险仍需按节点处理

- GKE 安全公告页显示 2026-06-18 的 GCP-2026-037 涉及 containerd 多个 CVE，可导致 Kubernetes 安全边界绕过、宿主机影响、缓存投毒或 DoS；6 月 20 日补充了 COS 节点修复版本，Ubuntu 节点修复仍在处理中。
- 虽然不在 24 小时内首次发布，但仍与当前 runc 事件形成同一类风险：升级控制面不等于节点运行时已安全。
- 建议：云上 K8s 要明确“节点池升级 / 轮换 / 重建”的执行状态，尤其是自定义镜像、Ubuntu 节点和长期运行节点。

### 5. 监控栈暂无 24 小时内新高危公告，但 Grafana 历史高危仍值得纳入巡检

- Grafana 官方安全公告页最近一条为 2026-06-13 Grafana Operator 中危路径穿越；5 月有多项高危/中危，3 月有 SQL Expressions RCE。
- 未发现 Prometheus 官方博客在过去 24 小时内发布新的安全公告。
- 运维意义：监控系统往往有高权限凭据、告警 Webhook、数据源密钥；即使没有新 CVE，也应检查公网访问、SSO、匿名访问、插件版本和备份。

## 对 OpenClaw / Hermes / 个人服务器有用的 3 条

1. 立刻盘点容器运行时版本。
   - 检查 `runc --version`、Docker/containerd 包版本、宿主机发行版安全更新状态。
   - 如果运行自建容器、OpenClaw/Hermes 相关服务或 CI 构建容器，优先更新 runc，并在更新后重启 Docker/containerd 或重建节点。

2. 把“容器不等于安全边界”写入运维基线。
   - 避免运行不可信镜像；固定镜像 digest；尽量使用私有 registry、镜像签名或至少启用镜像来源白名单。
   - 对 OpenClaw/Hermes 这类会接触凭据、消息通道和自动化工具的服务，容器内 root、特权容器、宿主机 Docker socket 挂载都应重新审视。

3. 对外服务做一次 KEV 快速排查。
   - 检查反向代理、DNS、Docker Compose、systemd 服务和旧测试目录，确认没有 ColdFusion、Joomla 插件、Langflow、远程协助工具、旧管理面板暴露公网。
   - 若使用 Grafana/Prometheus/备份平台，确认没有匿名访问、默认密码、宽泛 API token 或未加限制的 webhook。

## 风险 / 机会

### 风险

- runc 漏洞属于“低频但高后果”：需要攻击者有启动容器或供应链入口，但一旦满足条件可能影响宿主机。
- 仅升级 Kubernetes 控制面或应用镜像不足以修复节点运行时漏洞；必须关注宿主机包、节点镜像、托管节点池轮换。
- CISA KEV 新增项偏 Web 应用和插件，个人服务器最容易因“临时部署、测试服务、忘记下线”而中招。
- 扫描器 CVE 激增可能造成误判和疲劳；需要用精确包名、版本和供应商公告复核。

### 机会

- 借 runc 事件补一条自动巡检：周期性采集 `runc`、`containerd`、`docker`、内核版本并进入 Obsidian/告警。
- 为 OpenClaw/Hermes 的容器部署建立最小权限模板：非 root、无特权、只读根文件系统、限制 Docker socket、最小挂载。
- 将 CISA KEV、Docker、Kubernetes、Grafana、云厂商安全公告做成固定订阅源，减少依赖泛搜索。

## 建议检查清单

- [ ] `runc --version` 是否达到修复版本或发行版已 backport 修复。
- [ ] `docker info` / `containerd --version` / 包管理器安全更新是否完成。
- [ ] 更新后是否重启容器运行时，必要时重建容器或节点。
- [ ] 是否存在特权容器、宿主机 Docker socket 挂载、`/proc`/`/sys`/`/var/run` 等敏感挂载。
- [ ] 是否允许不可信用户提交镜像、Dockerfile、CI job 或 Kubernetes Pod。
- [ ] 公网入口是否存在 KEV 涉及产品或类似 CMS/低代码/远程管理后台。
- [ ] Grafana/Prometheus/备份系统是否只在内网或 VPN 后访问，token 是否最小权限。
