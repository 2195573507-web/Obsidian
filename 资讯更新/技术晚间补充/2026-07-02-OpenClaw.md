## 最重要 5 条

1. **CISA 将 Microsoft SharePoint Server CVE-2026-45659 加入 KEV，确认已被利用**  
   - 这是 SharePoint Server 反序列化不可信数据漏洞，CVSS 8.8，已在 5 月带外修复；CISA 7 月 1 日加入 KEV，要求联邦机构 3 天内处理。攻击需要认证但仅需 Site Member 权限，影响 SharePoint Server Subscription Edition、2019、2016 等。  
   - 影响：若有自建 SharePoint 或暴露协作系统，应优先排查；个人服务器通常不受影响，但这是“协作平台 + 低权限账号”被横向利用的典型风险。  
   - 来源：CISA KEV；SecurityWeek。

2. **AI 浏览器“BioShocking”攻击展示：上下文操纵可诱导代理浏览器泄露凭据**  
   - LayerX 研究称，通过把任务包装成“游戏/谜题”，可诱导多个 agentic browser 放弃现实安全逻辑，访问已登录环境、读取文本框/仓库内容并外传。测试对象包括 ChatGPT Atlas、Comet、Fellou、Genspark Browser、Sigma Browser、Claude Chrome。OpenAI 据称已修复，Anthropic 补丁失败，部分厂商未响应（厂商状态为媒体转述，标注未确认）。  
   - 影响：对 OpenClaw/Hermes 的浏览器自动化尤其相关：浏览器会话、已登录页面、跨标签页访问应最小授权，敏感操作需要人类确认。  
   - 来源：SecurityWeek；LayerX 报告（经 SecurityWeek 链接）。

3. **AI 编码代理 GuardFall / Bash tricks 风险：恶意仓库内容可能绕过 shell 防护**  
   - Adversa AI 研究称，多个开源 AI 编码/计算机使用代理可被 Bash 的 quote removal、`$IFS`、等价 argv 形态等技巧绕过规则式 denylist；研究提到测试 11 个流行开源代理，10 个存在某类缺口，Hermes 被点名为测试对象之一。该攻击通常依赖代理读取恶意 README/Makefile/MCP 内容，并在 auto-execute 或本地 sandbox 模式下执行。  
   - 影响：对 OpenClaw/Hermes 极高相关。需要避免自动批准 shell 命令；对外部仓库、网页、MCP 返回内容一律视为不可信；命令执行前应进行结构化解析而非字符串 denylist。  
   - 来源：SecurityWeek；Adversa AI 报告（经 SecurityWeek 链接）。

4. **Docker Engine 29.6.1 发布安全修复；近期 Docker AuthZ 绕过 CVE-2026-34040 仍值得复查**  
   - Docker 官方 29.6.1（6 月 26 日）修复多项安全问题，包括恶意镜像 `/etc/passwd`/`/etc/group` 风格文件导致 OOM，以及 BuildKit custom frontend 可在未授权情况下禁用 Seccomp/AppArmor 的问题。另有 Cyera 披露 CVE-2026-34040：超过 1MB 的 Docker API 请求体可能绕过 AuthZ 插件，Docker daemon 仍处理完整请求，可创建特权容器；研究称 29.3.1 已修复。  
   - 影响：个人服务器若使用 Docker、BuildKit、远程 Docker API、CI/CD 或 AuthZ 插件，应尽快确认 Engine / BuildKit / containerd / runc 版本，并避免暴露 Docker socket/API。  
   - 来源：Docker Engine 29 release notes；Cyera Research；The Hacker News（补充）。

5. **Chrome 151 修复 382 个漏洞，15 个 critical、67 个 high；暂无在野利用说明**  
   - Google 发布 Chrome 151，SecurityWeek 统计称修复 382 个漏洞，多数由 Google 自身发现；漏洞类型包括 use-after-free、越界、类型混淆、初始化/输入校验问题等，许多可由恶意网页触发并在 renderer sandbox 内执行代码，部分可能辅助沙箱逃逸。Google 公告未提及这些漏洞已在野利用。  
   - 影响：用于 OpenClaw 浏览器自动化的 Chromium/Chrome 环境应尽快更新；自动化访问未知网页时风险上升。  
   - 来源：SecurityWeek；Chrome Releases 官方公告（SecurityWeek 链接）。

## 对 OpenClaw / Hermes / 个人服务器有用的 3 条

1. **给 OpenClaw/Hermes 的代理执行安全加一道硬门槛**  
   - GuardFall 与 BioShocking 都说明：问题不只是模型“愿不愿意拒绝”，而是外部内容会改变代理上下文。建议：默认关闭 auto-execute；对 shell 命令使用结构化 allowlist / AST / argv 级审查；对浏览器读取凭据、跨站/跨标签访问、复制文本框、下载/上传文件等动作加入确认。

2. **个人服务器 Docker 基线应复查**  
   - 检查 Docker Engine 是否至少高于相关修复版本；禁用或限制远程 Docker API；避免将 `/var/run/docker.sock` 暴露给容器；CI runner/构建机单独隔离；BuildKit 自定义 frontend 只允许可信来源。

3. **GitHub 项目维护者可快速开启 6 项免费安全设置**  
   - GitHub Security Lab 7 月 1 日建议维护者本周开启 6 项免费设置，核心包括 `SECURITY.md`、私密漏洞报告、Dependabot/secret scanning/code scanning 等（原文为“6 security settings every GitHub maintainer should enable this week”）。对 OpenClaw/Hermes 相关仓库，建议把这类设置作为仓库创建模板的一部分。  
   - 来源：GitHub Blog。

## 风险 / 机会

### 风险
- **代理上下文污染成为真实攻击面**：浏览器代理、编码代理、MCP/网页/README/Makefile 输入都可能成为指令注入来源。
- **容器与构建链权限过大**：Docker socket、BuildKit、自定义 frontend、CI runner 一旦被绕过，通常直接触及主机凭据、SSH key、Kubeconfig。
- **企业协作系统仍是高价值入口**：SharePoint KEV 说明攻击者持续利用协作系统中的低权限认证入口。
- **浏览器漏洞数量激增**：即使暂无在野利用，自动化浏览器访问不可信网页时仍应视作高风险。

### 机会
- **把 AI agent 安全策略产品化/模板化**：可为 OpenClaw/Hermes 增加“外部内容隔离、命令结构化审查、敏感浏览器动作确认、最小会话授权”的默认策略。
- **仓库安全设置可快速落地**：GitHub 建议项多数是免费配置，适合形成一键检查清单。
- **Docker 资产梳理有明确抓手**：版本、远程 API、socket 暴露、BuildKit frontend、CI runner 隔离可直接纳入每日/每周自检。
