# 知识库召回问题排查

> 全量扩写知识页。上级入口：[[AI/RAG/RAG 与知识库评测手册|RAG 与知识库评测手册]]、[[MOC|知识库导航]]。

当知识库问答找不到内容时，按文件存在、索引缓存、embedding、查询改写、权限过滤、答案引用六层排查。先确认 Markdown 文件真实存在，再检查 Web/recall health 的 files_count 和 cached_items。

## 标准执行模板

1. 明确目标、范围和不做事项。
2. 收集当前证据：文件、服务、日志、配置、健康接口或历史报告。
3. 给出最小可执行方案，并保留回滚路径。
4. 执行后验证：读回文件、运行测试、访问接口或检查 Git diff。
5. 将稳定经验沉淀到知识库，临时状态写入报告而不是长期记忆。

## 检查清单

- 是否有 frontmatter、更新时间和分类。
- 是否至少链接一个上级 MOC。
- 是否区分稳定事实与实时状态。
- 是否避免泄露密钥、token、隐私和内部未授权信息。
