# 任务产物证据链设计

> 上级入口：[[AI/AI MOC|AI MOC]]、[[软件工程/测试与质量保障体系|测试与质量保障体系]]。

## 目标

Agent 完成任务时，不能只说“已完成”。产物证据链用于证明：做了什么、在哪里、如何验证、哪些风险仍然存在。

## 证据类型

- 文件证据：路径、hash、行数、关键片段。
- 测试证据：命令、结果、失败摘要。
- UI 证据：截图、页面状态、可访问链接。
- 日志证据：run_id、时间、错误分类。
- 外部证据：来源链接、版本号、发布时间。

## 报告结构

1. 结论：完成/部分完成/阻塞。
2. 产物：文件或链接。
3. 验证：执行过的检查。
4. 变更范围：新增、修改、未触碰。
5. 风险：待确认、未测试、外部依赖。

## 质量门

- 没有证据不宣称完成。
- 测试失败要说明失败项，不用“基本没问题”掩盖。
- 不能运行验证时说明原因。
- 对临时状态和长期知识分开记录。
