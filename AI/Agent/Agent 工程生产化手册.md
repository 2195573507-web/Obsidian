# Agent 工程生产化手册

> 本文是服务器知识库全量扩写的一部分，用于把零散经验沉淀为可复用知识。相关入口：[[AI/AI Agent 知识地图|AI Agent 知识地图]]、[[agents/index|Agent 总览]]、[[shared-memory/README|共享记忆说明]]。

## 适用场景

- 作为日常排障、设计评审、方案写作和 Agent 执行任务时的背景材料。
- 用于把一次性经验转成稳定 SOP，减少重复解释。
- 适合和服务器现有 [[server/服务器运维 Runbook|服务器运维 Runbook]]、[[agents/index|Agent 总览]]、[[shared-memory/README|共享记忆说明]] 联动使用。

## 核心原则

1. **先观测再行动**：所有配置、服务、数据库和知识结构修改前，先确认当前状态、备份点和回滚路径。
2. **最小可验证变更**：每次只改变一个可解释的变量，并记录命令、输出、时间和影响面。
3. **知识可追溯**：稳定事实写入 wiki，临时状态写入报告，危险动作保留人工确认。
4. **自动化但不自动删除**：可以批量生成索引、候选清单和质量报告，但重复文件、旧记忆、服务配置不自动删除。

## 操作清单

- 明确目标：这是排障、设计、扩写、迁移、审计还是复盘。
- 收集证据：文件、日志、服务状态、Git diff、健康接口、最近报告。
- 建立链接：新笔记至少链接一个 MOC 或上级主题，避免孤立知识。
- 验证结果：读回文件、检查 frontmatter、检查 wikilink、必要时访问 Web/health 接口。

## 常见风险

- 把日报或巡检报告当成永久事实，导致过期信息污染决策。
- 缺少 frontmatter、缺少链接，知识库变成不可导航的文件堆。
- 将服务器实时状态写死到概念笔记中，而不是链接到带时间戳的体检报告。
- 为了“整理”而删除历史资料；正确做法是先生成重复/过期候选报告。

## 生产化架构

一个可长期运行的 Agent 系统通常分为：入口层、编排层、工具层、记忆层、观测层、审批层。入口层处理 QQ/Telegram/Web/API；编排层负责任务拆解、重试、并发和上下文压缩；工具层统一文件、终端、浏览器、搜索、cron；记忆层区分用户偏好、稳定事实、项目知识和临时报告；观测层记录调用、失败、成本、延迟和产物路径；审批层控制删除、发布、推送、证书、网关、系统服务等高风险动作。

本服务器上可把 Hermes、OpenClaw、Atlas Notes、Shared Memory、Obsidian 看成一套组合：Hermes 执行任务，OpenClaw 负责多通道/节点控制，Shared Memory 存稳定事实，Obsidian 作为可读知识中心，Atlas Notes 提供 Web 查看。

## 质量门禁

- 每个 Agent 任务必须有目标、输入、约束、产出路径和验证方式。
- 后台任务必须区分 no-agent watchdog 与 LLM 推理任务，避免把简单监控交给昂贵模型。
- 长任务优先拆成数据采集、分析、写入、验证四段，任何一段失败都要保留可重跑状态。
- 所有自动生成知识都应标注生成时间、依据和不确定性。
