# Agent 运行失败分级与重试策略

> 上级入口：[[AI/AI MOC|AI MOC]]、[[AI/Agent/Agent 工程生产化手册|Agent 工程生产化手册]]、[[运维/可观测性与日志体系|可观测性与日志体系]]。

## 问题背景

Agent 任务失败不应该只记录为“失败”。生产化系统需要区分：模型上游不可用、工具调用超时、外部服务限流、权限审批缺失、上下文过大、结果校验未通过、投递通道失败等不同类型。只有分级清楚，重试策略才不会把短暂故障放大成任务风暴。

## 失败分级

| 级别 | 类型 | 典型信号 | 推荐处理 |
|---|---|---|---|
| L1 | 瞬时失败 | 502、504、连接重置、短超时 | 指数退避重试 1-3 次 |
| L2 | 限流失败 | rate limit、429、quota exceeded | 延迟到下个窗口，降低并发 |
| L3 | 上下文失败 | token 超限、摘要失败、检索过宽 | 压缩输入，分片执行 |
| L4 | 工具失败 | 文件不存在、API schema 错误 | 修正参数后再跑，不盲重试 |
| L5 | 安全/权限失败 | approval required、access denied | 等待人工授权或降级为报告 |
| L6 | 质量失败 | 校验不通过、结果为空、来源不足 | 进入人工复核或二次采样 |

## 重试策略

1. 对 L1 使用短退避：30 秒、2 分钟、5 分钟。
2. 对 L2 使用长退避：15 分钟、1 小时、下个自然任务窗口。
3. 对 L3 先降上下文：只保留目标、输入索引、最近错误、验收条件。
4. 对 L4 不自动重复相同参数，必须记录修正点。
5. 对 L5 永远不绕过审批，改为生成待审批说明。
6. 对 L6 保存失败产物，便于复盘质量门槛。

## 运行记录字段

建议每次 Agent 任务至少记录：任务名、run_id、开始/结束时间、模型/provider、失败级别、错误摘要、输入规模、工具调用摘要、是否投递成功、是否需要补跑、补跑建议。

## 验收清单

- 是否能从日志直接判断失败类型。
- 是否避免同一任务在 5 分钟内无限重试。
- 是否支持“低并发补跑”。
- 是否把投递失败和任务失败分开记录。
