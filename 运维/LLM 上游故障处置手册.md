# LLM 上游故障处置手册

> 上级入口：[[运维/运维 MOC|运维 MOC]]、[[AI/模型路由、成本控制与降级|模型路由、成本控制与降级]]。

## 现象

常见报错包括：`LLM request failed`、502 upstream、rate limit、agent couldn't generate a response、请求超时、模型返回空内容。若多个无关任务同时失败，优先怀疑上游或网关，而不是单个任务逻辑。

## 快速判断

1. 是否多任务同时失败。
2. 是否同一 provider/model 失败。
3. 是否失败在 agent-run 而不是业务工具。
4. 是否短时间内并发补跑过多。
5. 是否网关或服务刚重启。

## 处置步骤

1. 暂停批量补跑，防止扩大限流。
2. 用一个轻量任务验证模型是否可用。
3. 如果轻量任务失败，切 fallback 模型或等待恢复。
4. 如果轻量任务成功，再按低并发补跑关键任务。
5. 为失败任务补充错误分类，便于下次自动降级。

## 降级方案

- 报告类任务：改成本地资料汇总，不强制联网。
- 资讯类任务：只保存待补状态和来源清单。
- 巡检类任务：输出 checklist，不生成长报告。
- 投递类任务：先写文件，稍后再通知。

## 复盘问题

- 是否有 fallback 模型。
- 是否有并发上限。
- 是否区分任务失败和通知失败。
- 是否能从日志恢复待补列表。
