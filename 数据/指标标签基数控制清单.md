# 指标标签基数控制清单

> 上级入口：[[数据/数据 MOC|数据 MOC]]、[[运维/流式 API 可观测性指标|流式 API 可观测性指标]]。

## 背景

Prometheus/metrics 系统最常见的失控原因之一是 label 基数过高。Agent 和 LLM 系统尤其容易把 request_id、prompt、用户输入、URL、文件路径误放进 label。

## 可作为 label

- provider
- model
- route
- method
- status_code
- error_type
- task_type
- environment

## 不应作为 label

- request_id
- prompt / completion
- token / key / cookie
- 用户 ID 或聊天 ID
- 完整 URL
- 文件绝对路径
- session_id / run_id
- 任意自由文本错误信息

## 替代方案

高基数字段进入日志或 trace，不进入 metrics label。指标只保留聚合维度；需要定位单请求时通过 request_id 在日志系统查询。

## 检查清单

- 新增指标是否评估 label 基数。
- 是否有 label allowlist。
- 是否有异常 cardinality 告警。
- 是否禁止敏感字段进入 label。
- 是否区分 metrics、logs、traces 的用途。
