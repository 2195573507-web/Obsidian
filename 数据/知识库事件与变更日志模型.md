# 知识库事件与变更日志模型

> 上级入口：[[数据/数据 MOC|数据 MOC]]、[[数据/事件日志与审计表设计|事件日志与审计表设计]]。

## 目标

知识库需要知道内容为何变化、谁触发、生成依据是什么、是否需要复核。事件与变更日志模型用于连接文件系统、Agent 任务和人工维护动作。

## 核心实体

- `knowledge_file`：路径、标题、分类、更新时间、hash、字数、链接数。
- `change_event`：事件时间、操作者、来源任务、变更类型、影响文件。
- `quality_signal`：缺 frontmatter、弱链接、重复、短文、过期、敏感风险。
- `review_item`：待复核原因、优先级、状态、处理备注。

## 事件类型

| 类型 | 说明 |
|---|---|
| create | 新建页面 |
| update | 更新页面 |
| append | 追加管理块或索引 |
| validate | 执行质量检查 |
| duplicate_detected | 发现重复内容 |
| review_requested | 进入待整理清单 |

## 最小字段

每条事件至少包含：`event_id`、`timestamp`、`actor`、`source`、`operation`、`path`、`before_hash`、`after_hash`、`summary`。

## 使用场景

- 判断一次扩容实际新增了多少有效页面。
- 回滚误生成内容。
- 给 Agent 提供检索索引。
- 追踪重复内容和短文趋势。
