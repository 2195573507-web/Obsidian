# 团队目标与 OKR 设计

> 用于把长期愿景拆成季度目标、关键结果和可跟踪行动。

上级入口：[[MOC|知识库导航]]。

## 使用方法

先判断当前问题属于概念理解、方案设计、执行清单、复盘总结还是决策评估。概念笔记用于建立共同语言；SOP 用于可重复执行；模板用于减少从零开始；案例库用于积累经验；指标和检查清单用于验收。

## 沉淀原则

知识库扩容不是堆资料，而是把可复用的方法、边界条件、失败模式和验证方式写清楚。长期有效的内容写成 wiki；依赖日期、市场、服务状态和价格的信息必须标注时间或作为报告归档。

## OKR 结构

目标要描述方向和价值，关键结果要可度量、可验收、可在周期结束时判断完成程度。一个团队每周期 3~5 个目标即可，关键结果不宜超过 3 条。任务列表不是 KR，KR 应体现结果变化，例如交付周期缩短、可用性提升、收入增长、缺陷率下降。

## 复盘方式

周期结束时按事实评分：完成度、阻塞原因、指标是否选错、是否有副作用。复盘输出下一周期的调整，而不是追责。

## 快速检查清单

- 这篇笔记是否有明确适用场景。
- 是否能链接到至少一个上级 MOC 或相关主题。
- 是否区分通用方法、模板和需要实时验证的事实。
- 是否能被 Agent 在执行任务时直接引用为步骤、清单或判断框架。
