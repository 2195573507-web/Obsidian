# 后台任务幂等性设计

> 上级入口：[[软件工程/软件工程 MOC|软件工程 MOC]]、[[运维/Cron 定时任务补跑 Runbook|Cron 定时任务补跑 Runbook]]。

## 问题

后台任务会遇到超时、重复投递、人工补跑、worker 崩溃、网络重试等情况。如果任务没有幂等性，补跑可能生成重复报告、重复扣费、重复通知或覆盖正确结果。

## 设计目标

- 同一业务键重复执行，结果可预测。
- 失败后可以安全补跑。
- 通知和产物写入可分开确认。
- 运行记录能解释每一次执行。

## 常用业务键

- 日报：`task_name + date + audience`。
- 文件生成：目标路径或内容 hash。
- 消息通知：`run_id + channel + recipient`。
- 数据同步：源游标、目标表、时间窗口。

## 实现模式

1. 任务开始前写入 run record。
2. 产物写入临时文件，通过校验后原子替换。
3. 通知发送记录 message_id，避免重复通知。
4. 失败保留中间状态，但不标记完成。
5. 补跑时先检查目标产物是否已存在且有效。

## 验收清单

- 重跑同一任务不会产生多份同名日报。
- 通知失败不会导致正文重新生成。
- 部分成功能被识别。
- 人工补跑有 run_id 和原因。
