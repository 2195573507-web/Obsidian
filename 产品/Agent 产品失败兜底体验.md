# Agent 产品失败兜底体验

> 上级入口：[[产品/产品 MOC|产品 MOC]]、[[产品/AI 功能风险提示与人工接管|AI 功能风险提示与人工接管]]。

## 背景

Agent 产品不能假设每次都会成功。上游模型、工具、权限、网络、外部 API 都可能失败。好的兜底体验不是隐藏失败，而是让用户知道：发生了什么、已经完成了哪些部分、下一步怎么恢复。

## 兜底信息结构

1. 状态：已完成、部分完成、未开始、失败。
2. 原因：可理解的错误类别，不暴露敏感内部细节。
3. 影响：哪些目标没达成，哪些产物已保存。
4. 选项：重试、低并发重试、稍后提醒、人工处理、查看日志摘要。
5. 保证：不会重复扣费/重复通知/覆盖已有文件的说明。

## 设计原则

- 先说结论，再给细节。
- 不把技术异常甩给用户。
- 对长任务给中间状态和可恢复入口。
- 对危险操作明确等待确认。
- 对重复失败建议改变策略，而不是无脑重试。

## 示例文案

“这批任务已入队 3 个，但后续任务因 runner 启动超时暂停。我建议改成每批 2 个继续补跑，避免再次压垮队列。”

## 验收清单

- 用户能判断是否需要等待。
- 用户知道是否会自动继续。
- 用户能看到已保存产物。
- 用户不需要理解内部堆栈也能做决定。
